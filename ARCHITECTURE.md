# Архитектура

PocketBook Cloud skill разделяет диалоговую логику и детерминированную интеграцию.

```text
Пользователь
   ↓
OpenClaw + SKILL.md
   ↓ намерение, выбор книги, подтверждение
scripts/pocketbook.py
   ↓
pocketbook_lib/
   ├─ api.py        API, password-login и проверка контрактов
   ├─ state.py      приватная сессия, атомарная запись и locks
   ├─ transport.py  безопасная загрузка по недоверенным URL
   ├─ formats.py    EPUB/FB2/ZIP и защита архивов
   ├─ models.py     поиск, неоднозначность, progress/notes
   ├─ operations.py batch, backup, chat delivery и delete workflow
   └─ common.py     ошибки, лимиты и общие примитивы
   ↓
PocketBook Cloud
```

## Граница агента и helper

OpenClaw интерпретирует запрос пользователя и управляет диалогом. Python helper не «рассуждает»: он валидирует состояние, пути, форматы, ответы API и выполняет только выбранную операцию. Текст книг, заметок, названия файлов и поля API считаются недоверенными данными и никогда не становятся инструкциями агенту.

## Авторизация

Новый вход использует обычные учётные данные PocketBook Cloud: email и пароль. Команда `auth login` спрашивает email в терминале и пароль скрыто через `getpass`. Пароль используется только для password-login и не записывается на диск.

Для consumer API helper также использует client interoperability values браузерного клиента PocketBook. Они публично поставляются самим web-клиентом провайдера и не являются пользовательскими credentials.

После успешного входа локально хранится только access/refresh session. Состояние находится вне Git, каталог 0700, session-файл 0600. Refresh сериализован lock-файлом и записывается атомарно.

## Безопасный transport

API-запросы идут только к ожидаемому HTTPS origin. Для скачивания файлов используются URL, возвращённые библиотекой, но PocketBook Authorization header на файловый хост не переносится.

Перед соединением URL проверяется на HTTPS, отсутствие userinfo и допустимый порт. DNS-ответы проверяются на публичные адреса; private/loopback/link-local блокируются. Redirect проверяется заново. Соединение закрепляется на уже проверенном sockaddr, чтобы не делать повторное DNS-разрешение между проверкой и connect.

## Файлы и архивы

Форматный слой отличает настоящий EPUB от transport ZIP, валидирует FB2/FB2.ZIP и обрабатывает случай Telegram, где FB2 может прийти как XML.

Для архивов блокируются traversal, абсолютные пути, symlink/special entries, дублирующиеся имена после flattening, чрезмерное число файлов, объём распаковки и подозрительный compression ratio. Временные файлы создаются отдельно и публикуются атомарно; существующие назначения не перезаписываются молча.

## Upload verification

HTTP 2xx не считается достаточным доказательством загрузки. После upload helper ищет индексированную запись Cloud и сопоставляет идентичность по hash, имени, размеру и формату. Если сервер принял тело, но итоговая запись не подтверждена, операция остаётся unverified.

## Batch

До multi-book transfer выполняется preflight: число книг, оценка размера и проверка всех входов. По умолчанию отдельное подтверждение требуется при более чем 10 книгах или более 100 MiB. Подтверждённый повтор явно передаётся через `--confirmed`.

## Удаление

Удаление разделено на два пользовательских сообщения.

1. `delete prepare` разрешает ровно одну книгу и создаёт краткоживущий pending-state, привязанный к аккаунту и идентичности книги.
2. Агент заканчивает ход.
3. Только следующее явное сообщение пользователя передаётся в `delete confirm`.
4. Перед destructive request helper повторно проверяет аккаунт и книгу, а pending-state потребляется до сетевого вызова.

Legacy confirmation codes неактивны. Неоднозначный результат удаления не превращается в выдуманный успех.

## Тестовая граница

Тесты не используют реальный аккаунт или live API. Contract fixtures проверяют ожидаемые схемы API, hardening tests покрывают filesystem state, URL transport, архивы, race-sensitive state и destructive workflow. Публичный репозиторий добавляет release-gate regressions.
